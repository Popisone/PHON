\## 4. Hybrid v3 pipeline (production design)



\### Дизайн



&#x20;   def hybrid\_extract(question):

&#x20;       # 1. Regex first (80% cases, <1ms)

&#x20;       r = regex\_extract(question)

&#x20;       if all(r.values()): return r, "regex"

&#x20;       # 2. Qwen + Outlines fallback (20% cases, 4.4s)

&#x20;       try:

&#x20;           r = qwen\_extract(question)

&#x20;           if all(r.values()): return r, "llm"

&#x20;       except: pass

&#x20;       return None, "fail"



\### Coverage breakdown (v10 §5)



\- \*\*Regex (16/20)\*\*: ясни единици, всички числа, шаблонни формулировки

\- \*\*LLM (4/20)\*\*: natural language variations — "compressed by 4", "factor of N",

&#x20; "compressed 6 times", различен word order

\- \*\*Combined\*\*: 20/20 на held-out test set



\### Latency (warm Qwen)



\- Regex case: <1ms

\- LLM case: 4.4s

\- Mean 10 cases: \~880ms (8×1ms + 2×4400ms)



\## 5. Failure progression (v10 §3) — КРИТИЧНО ЗА PAPER



\### v3 extraction failure progression



| Опит | Модел | LoRA | Dataset | Loss plateau | Output |

|---|---|---|---|---|---|

| 1. v3 стар | SmolLM-135M + v2-merged | r=8 (460K) | 1000 | 0.24 | Garbage text |

| 2. v3-v2 | SmolLM-135M (fresh) | r=16 (921K) | 2000 | 0.24 | Garbage text |

| 3. Qwen | Qwen2.5-0.5B | r=16 (2.1M) | 2000 | 0.23 | Chat-format text |



\*\*Изводът:\*\* Loss \~0.23-0.24 е capacity limit за precise numeric extraction от

free-form text при 135M-500M параметри. Не е training recipe проблем

(3 опита, 3 модела, същата стойност).



\*\*Решението:\*\* Outlines CFG (constrained decoding) — принуждава модела да произведе

валиден JSON. Loss остава 0.23, но структурата е гарантирана. Qwen + Outlines = 20/20.



\### Защо SmolLM fail-на, Qwen работи



\- SmolLM няма JSON prior → Outlines помага, но числата не са точни

\- Qwen е виждал много JSON в pre-training → Outlines отключва latent знание

\- Изводът: изборът на base model има значение, дори loss-ът да е същият

\## 11. Технически уроци (v10 + v11)



\*\*PowerShell 5.1:\*\*



1\. `\[System.IO.File]::ReadAllText("relative/path")` → гърми. .NET CWD ≠ PowerShell PWD.

&#x20;  Always absolute path or `Resolve-Path`.

2\. `"string".Split("anchor")` split-ва по \*\*символи\*\*, не по substring.

&#x20;  За проверка на уникалност: `$t.IndexOf($a) -eq $t.LastIndexOf($a) -and $t.IndexOf($a) -ge 0`.

3\. Here-string `@'...'@` за 200+ реда с `"` вътре е чуплив при paste.

&#x20;  За дълги текстове: `@(...)` array от редове + `\[System.IO.File]::WriteAllLines`.

4\. `git commit -m "..."` с multi-line body → hook отхвърля. Single-line only.

5\. `python -c "..."` с `\\"` вътре → обърква quoting. Ползвай here-string за Python.



\*\*Python:\*\*



6\. `np.load()` weights са `(out, in)` за PHON simulator. sklearn дава `(in, out)` → `.T`.

7\. Softmax numerical stability: `exp(z - max(z))` преди division.

8\. `band x = 0` НЕ минава semantic валидация (positive freq).

&#x20;  За unit test: инжектирай tensor директно в `sim.tensors\["x"]`.

9\. Outlines работи само на Python 3.12 (`.venv312`), НЕ на 3.14.

10\. Torch InductorError (MSVC missing) е harmless — fallback работи.

&#x20;   Suppress: `os.environ\["TORCHDYNAMO\_DISABLE"] = "1"`.
