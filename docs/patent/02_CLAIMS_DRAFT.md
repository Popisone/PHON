# Draft Claims (Preliminary)

**Note:** These are preliminary claims for review by a patent attorney. Claims are drafted in a hybrid style (US + EPO friendly) and require refinement by counsel before filing.

## Independent Claims

**Claim 1.** A computer-implemented method for compiling a declarative phononic circuit description, the method comprising:

(a) receiving a source program in a declarative phononic orchestration notation (PHON) language, the source program comprising at least one medium declaration, a plurality of component declarations, and at least one flow block;

(b) tokenizing the source program into a token stream;

(c) parsing the token stream using a LALR(1) parser to produce an abstract syntax tree (AST), wherein the parser is cached so that repeated parses of the same source produce an identical AST in constant time;

(d) performing semantic analysis on the AST, the semantic analysis comprising at least: (i) checking for duplicate component identifiers, (ii) resolving all identifier references in flow statements to declared components, (iii) validating that numeric parameters satisfy physical constraints (ratio > 0, bandwidth > 0, frequency > 0), and (iv) verifying that all detector references are preceded by detector declarations;

(e) serializing the AST into a machine-readable hardware description format, the serialization preserving operator tokens including directional arrows, range operators, and equality operators;

(f) executing the hardware description with a physics-consistent simulator that computes at least one output selected from: (i) a logic bit from constructive or destructive interference, (ii) a compressed output frequency equal to an input frequency divided by a compression ratio, and (iii) a transmission rate equal to a channel bandwidth multiplied by a predefined throughput constant.

**Claim 2.** The method of claim 1, wherein the component declarations are selected from the group consisting of: resonator, waveguide, detector, compressor, and channel.

**Claim 3.** The method of claim 1, wherein the compression ratio is a parameter of a compressor component, and the compressed output frequency is computed as `freq_in / ratio`.

**Claim 4.** The method of claim 1, wherein the transmission rate is computed as `bandwidth_GHz * 100 Gbps`.

**Claim 5.** The method of claim 1, further comprising training a machine learning surrogate model on a dataset of (input parameters, simulator output) pairs generated by the physics-consistent simulator, and exporting the trained model to a portable format selected from: ONNX, a C language header, or a pickle file.

**Claim 6.** The method of claim 5, wherein the surrogate model is served via an HTTP REST API exposing endpoints for single prediction, batch prediction, health check, and performance benchmarking.

## Dependent Claims

**Claim 7.** The method of claim 1, wherein the flow block comprises a `for` loop statement with explicit lower and upper bounds, and the semantic analysis verifies that the bounds are integers and that the lower bound is less than or equal to the upper bound.

**Claim 8.** The method of claim 1, wherein the flow block comprises a `capture` statement that stores the current amplitude of a source component into a target resonator, and a `read` statement that retrieves a snapshot of the stored value.

**Claim 9.** The method of claim 1, wherein the physics-consistent simulator computes interference intensity according to `I = A1^2 + A2^2 + 2*A1*A2*cos(phi1 - phi2)` and compares the result against a configurable detector threshold.

**Claim 10.** The method of claim 1, wherein the parser is configured to fall back from LALR(1) to Earley parsing for source files that are not LALR-parseable.

**Claim 11.** A system for phononic circuit design, comprising: a processor; a memory storing instructions that cause the processor to execute the method of claim 1; and a network interface configured to expose the method as a REST API endpoint.

**Claim 12.** A non-transitory computer-readable medium storing instructions that, when executed by a processor, cause the processor to execute the method of claim 1.

## Notes for Attorney

- **Novelty argument:** The combination of (a) declarative DSL with three-level architecture, (b) LALR + caching pipeline, and (c) physics-consistent simulator that computes compression and transmission as first-class operations, is not disclosed in the prior art we are aware of.
- **Inventive step argument:** Existing phononic design tools are either full-wave (FDTD) or rely on SPICE-like netlists. PHON abstracts at the logic level while remaining physically grounded (interference formula).
- **Claim 1 preamble:** Consider broadening to "declarative hardware description language" if counsel advises.
- **Claim 5:** The ML surrogate may be pursued as a separate divisional if the examiner objects.
